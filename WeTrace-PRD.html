1背景与目标

1.1 需要解决的问题

微信消息持续增长，跨时间查找、回看和整理的成本越来越高。用户需要一个本地工具持续追踪已经同步的消息，并能按会话、时间和关键词找到原文。

1.2 产品决策

做一个本地优先的消息追踪工具。当前主线是“连接微信 → 同步消息 → 查看会话 → 搜索与日期定位 → 生成消息总结”，首先把消息接入、浏览、追踪和回顾做完整。

1.3 目标

  • 用户能连接本地微信并增量同步联系人、私聊、群聊和消息，重复同步不产生重复消息。
  • 用户能通过会话列表和聊天窗查看私聊与群聊记录，并按关键词或日期定位本地消息。
  • 用户能按日度、月度、年度生成会话总结，也能提取当前微信本人全年在私聊和群聊中发送的消息，生成个人年度总结并回跳原文。
  • 取钥开库后，消息浏览、同步、总结和导出不依赖微信持续运行。
  • 原始聊天数据保存在本机；只有用户主动使用 AI 功能时，才向其配置的 Provider 发送当前任务所需的数据。

1.4 首版完成标准

  • 用户能够从首次连接进入会话列表，并打开私聊或群聊聊天窗查看已同步记录。
  • 消息搜索、日期定位、同步和原文回跳可用，加载、空数据与失败状态均有明确反馈。
  • 会话总结与个人年度总结均使用明确的自然周期和本地数据范围；个人年度总结只包含本人发送的消息，无消息时不调用 AI。
  • 同步重跑无重复消息，微信退出后仍可读取本地数据，历史消息与已保存总结不因任务失败丢失。

3.3 明确不做（首版）

  • 不根据聊天自动判定“已经恋爱”“已经分手”“不爱了”或任何单方面的关系事实。
  • 不做忠诚、出轨、欺骗、心理疾病等敏感推断，不做分手预测或挽回评分。
  • 不做隐蔽监控、机器人、云端账号或多端同步；P0 不提供消息发送。若后续加入发送能力，只有发送动作需要微信进程运行。
  • 消息追踪、会话总结和个人年度总结覆盖私聊与群聊；关系分析仍只针对双人私聊，其他 IM 留到后续。
  • 不产出单人人格画像、群成员画像矩阵或任何关系评分。

4核心用户旅程

4.1 首次连接：60 秒登录取钥

前置条件：微信必须停在“未登录窗口”。用户需要在微信内退出账号；只关闭微信窗口不符合条件。WeTrace 不代替用户退出账号或点击登录。
定位微信进程 PID→ 按平台建立读取能力→ 开启 60 秒抓取窗口→ 用户点击微信登录→ 读取 Key 并立即验证→ 加密落盘并只读开库

抓取窗口打开后，界面显示“现在可以去点登录了”和剩余秒数。数据库成功打开后，用户可以关闭微信；消息浏览、同步、分析和导出不依赖微信进程持续运行。

4.2 主流程：建立一段关系的时间线

连接微信并同步→ 选择私聊对象→ 创建关系档案→ 生成时间线→ 查看双方变化→ 确认 / 修改关键时刻→ 保存或导出

4.3 生成消息总结

选择会话总结 / 我的年度总结→ 选择周期→ 提取本地消息→ 生成统计与主要话题→ 回跳原文或保存导出

4.4 消息浏览与原文回跳

点击左侧「消息」→ 选择会话→ 查看私聊 / 群聊记录→ 搜索 / 日期定位 / 同步→ 私聊可创建或查看关系档案

从时间线、变化观察或消息总结点击证据时，也进入同一聊天窗，定位并高亮对应原文。

4.5 异常与边界

  • 微信仍处于已登录状态 → 不启动 60 秒窗口，引导用户退出账号并重新检测。
  • 抓取超时、用户取消或进程退出 → 清理本次读取能力，保留旧数据与旧密钥，可重新发起。
  • 历史消息不完整 → 时间线起点标为“本地记录起点”，不得写成“相识日期”。
  • 样本不足 → 仅展示消息与基础统计，不强行划分关系阶段。
  • 长期无消息 → 显示“该时段无本地消息”，不直接推断为冷战或疏远。
  • LLM 失败 → 保留已同步消息和统计，可重试 AI 部分；用户已确认内容不受影响。

B. 左侧导航与本人入口

触发：首次连接并完成同步后进入应用外壳，默认选中「消息」；之后启动时优先恢复上次选中的导航和会话。

规则：左侧导航至少包含「消息 / 关系 / 总结 / 设置」。左下角固定显示当前微信本人的头像；头像读取失败时显示昵称首字占位，不显示破图。点击头像打开账号浮层，展示本人昵称、连接状态、最近同步时间，以及「重新获取密钥」和「数据库与账号设置」入口。

结果：点击「消息」始终回到会话列表；切换导航不丢失正在查看的会话。账号浮层不展示完整密钥或完整 wxid。

C. 会话列表与聊天窗（私聊 / 群聊）

  • 会话列表：同时展示私聊和群聊，按最近一条本地消息时间倒序；每行显示会话头像、会话名称、类型标识、最近消息预览和消息时间。私聊显示名备注优先于昵称，群聊使用群名称；顶部搜索仅查询本地会话名称与备注，不调用 LLM。
  • 进入聊天：点击会话后，在右侧打开聊天窗；正文按发送时间正序展示，以日期分隔，本人消息在右，其他发送者消息在左。群聊中他人的消息须显示发送者头像与显示名，不能只按左右位置判断发送者。
  • 初始位置与分页：首次进入默认定位到最新消息；向上滚动按 50 条加载历史，加载期间保留当前滚动位置。从证据进入时改为定位目标消息并高亮，同时加载足够上下文。
  • 消息类型：文本直接展示；图片、语音、文件等未解析内容显示对应类型、发送方向和发送时间，不臆测正文。P0 聊天区只读，不显示发送输入框。
  • 本地可用性：已同步会话和消息在微信退出后仍可查看；网络断开不影响本地浏览、搜索和日期定位。

FR-01微信本地数据接入

触发：首次启动、已保存 Key 失效、用户从本人头像或设置中点击「重新获取密钥」，以及手动同步（P1 起可由自动化规则触发同步，但不自动发起取钥）。

规则：探测或手动选择本机微信数据目录；优先验证已保存 Key，不可用时才进入 60 秒登录取钥。验证通过后，以只读方式解密并增量同步联系人、私聊、群聊、群成员和消息；标准化会话类型与发送者身份，并确认当前微信本人映射。每批消息与游标同事务提交。

结果：显示连接状态、当前本人账号、私聊与群聊数量、消息数、最近同步时间和本地记录覆盖范围；不修改或写回微信原库。

A. 60 秒登录取钥流程

  1. 前置检测：确认微信已启动且停在“未登录窗口”。检测到已登录账号时，提示用户先在微信内退出账号；只关闭窗口不能通过检测。
  2. 定位进程：定位当前微信进程 PID，并绑定本次抓取任务。找不到进程、发现多个无法确认的实例或进程中途退出时，不进入倒计时。
  3. 建立读取能力：说明所需系统权限，经用户明确授权后，按 macOS / Windows 分别建立最小范围的进程读取能力。授权准备时间不计入 60 秒。
  4. 开启抓取窗口：读取能力就绪后才开始 60 秒倒计时，UI 显示“现在可以去点登录了”、剩余秒数和「取消」。用户自行回到微信点击登录，应用不自动操作微信。
  5. 读取并立即验证：只在本次登录派生 Key 时读取所需密钥材料；取得候选 Key 后立即尝试只读打开目标数据库并读取最小元数据，格式匹配不等于验证成功。
  6. 加密落盘并开库：验证成功后加密保存 Key，再建立只读连接并进入同步。只有密钥保存和数据库连接均成功，状态才变为“已连接”；此后微信进程可以关闭。

B. 状态与恢复

未连接 → 等待微信退出账号 → 准备读取能力 → 等待登录（60s）→ 验证中 → 已连接
   ↑             ↓                  ↓               ↓          ↓
   └─────────────┴──── 可取消 / 失败可重试 ─────────┴──── 需重新取钥
情况产品行为
微信未运行 / 已登录 / 实例不明确阻止开始倒计时，分别提供“打开微信后重试”“退出账号后重新检测”“关闭多余实例”的明确指引
用户取消授权或抓取立即结束本次任务并释放读取能力，不反复弹出授权，不修改已保存 Key
60 秒超时 / 微信进程退出停止抓取并清理临时数据；显示重新发起入口，旧数据和已验证旧 Key 保留
候选 Key 验证失败丢弃候选，不写入安全存储，不覆盖旧 Key；提示版本不兼容或重新抓取
加密保存失败不显示“连接成功”，允许重试保存或取消；不得退化为明文落盘
账号或数据目录发生变化停止同步并标记“需重新取钥”；不得把一个账号的 Key 用于另一个账号，已有本地数据不清空

C. 密钥与微信进程生命周期

  • Key 与当前微信账号、适配版本和数据目录绑定；再次启动时先验证已保存 Key，验证通过则跳过退出账号和抓取流程。
  • 只有验证成功的新 Key 才能替换旧 Key；替换前产生的已同步消息、关系内容和消息总结不受影响。
  • 取钥并完成只读开库后，浏览、搜索、同步、AI 分析和导出均不要求微信继续运行；若后续提供发送消息能力，仅发送前需要检查并引导启动微信。
  • 版本不兼容时停止同步并报告原因，不尝试写原库，也不通过反复扫描或反复授权规避系统限制。

FR-02关系档案

触发：用户在会话列表选择联系人并点击「创建关系档案」。

规则：固定绑定“当前用户 + 一个联系人 + 对应私聊”；用户可设置当前关系标签、备注和回忆，并通过手动 Moment 记录在一起、分手、见面等事实。当前标签不覆盖历史事实。

结果：档案展示双方、数据覆盖范围、用户确认的关系节点、基础互动统计和最近消息总结。

状态 / 异常：支持 active / archived；身份映射不明确时要求用户确认，不自动合并联系人；归档只隐藏档案，不删除消息。

FR-03关系时间线（核心）

触发：进入关系档案后手动生成，或打开一份已保存的时间线。

规则：

  1. 仅使用该关系对应私聊中、快照时间之前的消息；展示实际覆盖范围与缺口。
  2. AI 生成候选 Chapter 与 Moment；候选阶段使用“开始频繁联系”等可观察描述，不自动写入“恋爱”“分手”等关系事实。
  3. 每条 AI 内容必须带原文证据；用户可保留、修改、忽略，也可新增手动事实和回忆。
  4. 已确认内容在新一轮分析中保持不变；新结果作为新版本或候选内容呈现。

结果：按时间展示阶段、关键时刻、双方发言与互动统计，支持点击证据回跳原文。

状态 / 异常：候选内容为 pending，确认后为 confirmed，忽略后为 dismissed；样本不足时只显示消息与统计，不强行划分阶段。

FR-04双方变化回顾（核心）

触发：用户选择同一段关系内的两个时段，点击「对比变化」。

规则：分别标注“我 / TA / 双方互动”；本地计算发言数、主动发起率、回复间隔、活跃时段等统计，AI 只总结称呼、表达、话题和互动方式的可观察变化。跨时段对比使用同一指标口径，缺失或不可比时明确提示。

结果：并列展示两个时段的统计差异与 AI 变化观察；每条观察附对应时段的原文证据，用户可确认或否定。

状态 / 异常：任一时段无消息或样本不足时不生成该侧语义结论；无消息不等于冷战，统计差异不等于感情变化。

FR-05消息总结（会话 + 个人年度）

A. 通用规则

触发：用户在「总结」页选择「会话总结」或「我的年度总结」，设置目标与周期后点击「生成总结」；P0 均为手动生成。

周期规则：按本机时区划分自然日、自然月和自然年；当前未结束的周期统计至最近一次成功同步时间。总结必须标明目标、所选周期、实际数据覆盖范围和生成时间。

结果：保存可回跳原文的消息总结，区分本地统计与 AI 总结；历史总结可按总结类型、周期和时间查看、导出。

状态 / 异常：目标范围内无符合条件的本地消息时仅保存空总结，不调用 LLM；AI 不可用时仍可查看本地统计和消息明细；生成失败不影响历史总结。

B. 会话周期总结

范围：选择一个私聊或群聊，支持日度、月度、年度；使用该会话在所选周期内的全部本地消息。

内容：本地计算消息总量、本人发言数、活跃天数和活跃时段，AI 仅整理主要话题与重要消息摘要。所有 AI 摘要必须附原文证据，不生成关系判断、待办、活跃排行或工作汇报式结论。

C. 我的年度总结

范围：以当前微信本人和自然年为目标，提取该年在全部私聊和群聊中由本人发送的本地消息；统计与 AI 输入均只使用这些本人消息，不纳入他人发言。

提取规则：按已确认的发送者身份过滤，保留消息来源会话、会话类型、发送时间和原文引用；文本用于内容总结，未解析的图片、语音、文件仅计入类型与数量，不臆测正文。

内容：展示年度消息总量、私聊 / 群聊分布、覆盖会话数、活跃月份与日期、主要话题和重要消息摘要；支持按月份或来源会话查看本人消息明细，并从总结或明细回跳原会话中的对应消息。

身份异常：当前本人映射不明确或账号发生变化时禁止生成，先要求确认身份并重新同步，不得混合不同微信账号的消息。

FR-06AI 模型配置

触发：首次使用 AI 功能或进入设置。

规则：配置 OpenAI-compatible 地址、模型与 API Key；发送前显示数据范围和 Provider，密钥仅保存在系统安全存储中。

结果：连接测试返回可用性与模型信息，不返回或记录密钥。

状态 / 异常：未配置、鉴权失败、限流和输出无效均有明确错误；同步与本地统计不依赖 LLM，可继续使用。

FR-07本地存储与导出

触发：用户保存分析结果、主动导出或清空本地数据。

规则：消息、关系内容、任务与消息总结存本机 SQLite；导出 HTML / Markdown / PNG 时标明事实、统计和 AI 观察，保留证据链接对应的原文引用。

结果：导出至用户选择的位置；归档、删除关系派生内容和清空全部数据分别确认，避免误删原始同步数据。

状态 / 异常：导出失败不损坏已保存内容；无有效证据的 AI 结论不得进入正式结果或导出。

FR-08自动化 P1

触发：用户为指定会话或关系创建规则并启用 CRON 调度。

规则：动作限定为同步、生成消息总结、生成候选变化；保存目标类型与 ID、动作、CRON、时区、启用状态和执行历史。同一计划时间防重，同一规则串行执行。

结果：保存消息总结或候选观察，系统通知仅含任务名称、状态与本地跳转，不含聊天正文。

状态 / 异常：单次失败记录原因且不阻塞下次调度；无新消息时跳过 AI；自动任务不得修改用户已确认的事实或内容。

7隐私、权限与异常

红线：原始消息内容只允许流向两个目的地 —— ① 本机 SQLite；② 用户配置的 LLM Provider。绝不发送到 WeTrace 自己的服务器（首版也不设服务器）。
  • 微信原始数据库只读，不修改、不写回。
  • LLM API Key 与微信数据库 Key 均使用系统安全存储或操作系统保护的加密容器（macOS Keychain / Windows DPAPI），不写明文配置文件，不进入日志、导出文件或 Renderer。
  • 进程读取能力仅用于用户主动发起的登录取钥；不得保存完整内存转储，不得读取或上传与密钥派生无关的内容，任务结束后立即释放。
  • 导出消息总结由用户主动触发，导出路径用户自选；导出内容默认不含 wxid、头像等身份标识。
  • 关系档案涉及对方数据：仅本机可见，删除单个关系只删除派生分析内容，不触碰微信原库。
  • 提供「一键清空本地数据」按钮，二次确认中明确将删除 SQLite、缓存和已保存的微信 Key；完成后下次使用需重新连接。

8.5 微信同步管线

定位数据目录→ 验证已存 Key / 60 秒登录取钥→ 立即验证并加密保存→ 只读开库→ 全量或增量读取→ 标准化会话类型与发送者→ 事务 UPSERT→ 推进游标
  • 适配器隔离：微信版本差异与平台取钥差异封装在 WechatSourceAdapter 和原生读取组件中；上层只接收统一的 Person / Conversation / Message。
  • 进程解耦：Key 验证、加密保存和只读开库完成后，同步不依赖微信进程存活；微信退出或后续被用户关闭不得导致已打开任务清空本地数据。
  • 一致性：每批消息与游标在同一事务提交；来源消息键保证重复同步不产生副本。
  • 本人映射：发送者统一关联到本地 Person，并用当前微信账号确认 is_self；群聊发送者无法确认时保留未知状态，不得猜测为本人。
  • 并发：同步、时间线生成、消息总结可以并行读取；SQLite 写入串行化，避免数据库锁扩散到 UI。
  • 降级：无法识别微信版本时停止同步并报告 WECHAT_VERSION_UNSUPPORTED，不得尝试写原库。
  • 可恢复：应用重启后从最近已提交游标继续；失败批次整体回滚。

8.6 关系时间线生成管线（核心）

冻结输入快照→ 过滤与采样→ 确定性统计→ 语义分块→ 并行抽取→ 合并去重→ 证据校验→ 版本保存

A. 输入与采样

  • 按 relationship_id + sent_at <= snapshot_at 固定输入，运行中新同步的消息不得混入本次结果。
  • 只将文本消息送入语义分析；图片、语音、链接等保留类型与时间元数据，正文缺失时不臆测内容。
  • 统计与语义分离：双方发言数、主动发起率、回复间隔中位数、活跃时段由本地 SQL 计算，不交给 LLM。
  • 默认覆盖全部本地消息；超过输入预算（约 60k tokens）时按时间分层采样，近 3 个月全量保留，并在结果页显示实际覆盖范围与消息数。
  • 单关系消息少于 200 条或覆盖不足 30 天时，只展示消息与统计，不调用语义抽取。

B. 分块与模型调用

  • 按时间连续性分块，再按 Token 预算截断；每条消息携带内部 message_id、发送时间与发送方。
  • 同一批消息只做一次抽取调用，同时产出章节候选、关键时刻候选与变化候选，避免重复计费。
  • 分块任务有界并发（默认 3）；Provider 限流时指数退避，仅对超时、429 和可重试 5xx 重试，上限 3 次。
  • 每块输出固定 JSON Schema；解析失败进入 1 次修复重试，仍失败则标记该块失败，不伪造结论。
  • 汇总阶段只能引用分块结论及其证据，不得引入新事实。

章节 / 时刻不得写入“恋爱 / 分手 / 出轨”等关系事实仅保留为候选提示，必须由用户手动确认

E. 版本与用户确认

  • 每次生成写入新版本（保留最近 10 版）；已确认条目进入新版本后仍为 confirmed，不被自动改写。
  • 确认 / 修改 / 忽略只作用于单条章节、时刻或变化，不影响其他候选。
  • 用户手动新增的 Moment 不参与 AI 覆盖，只参与时间线展示与导出。

F. 变化对比（FR-04）

  • 用户在同一关系内选择两个等长时段，默认为最近 30 天 vs 前 30 天；先输出本地统计差异，再发起一次对比抽取。
  • 对比输入只包含两时段采样消息与统计表；输出维度限定为称呼、表达方式、话题、主动性与回复节奏。
  • 任一时段不足 50 条消息时只输出统计，不输出语义结论；两时段口径必须一致，不可比时明确标注。
时间线表达为“基于本地聊天样本的可观察变化”，不得输出心理 / 医学诊断，不得把模型推断表述为确定事实。样本不足的时段返回“数据不足”，不强行划分阶段。

8.7 消息总结生成管线

会话总结与个人年度总结复用 analysis_runs、分块、Provider Gateway 和证据校验。先按本机时区确定自然周期并冻结本地消息快照，再按总结类型提取消息；当前未结束周期的数据截至最近一次成功同步时间，无符合条件消息时生成空总结并跳过 LLM。

  • 会话总结：目标为 conversation_id + period_type + period_start，读取所选私聊或群聊的全部本地消息；由本地 SQL 计算消息量、本人发言数、活跃天数和活跃时段。
  • 个人年度总结：目标为 self_person_id + year，从全部私聊和群聊中筛选 sender_person_id = self_person_id 且处于所选自然年的消息；统计与 AI 输入均不得包含他人发言。
  • 证据校验：会话总结的引用必须属于目标会话；个人年度总结的引用必须是目标年份内本人发送的消息，并保留来源会话用于回跳。AI 仅整理主要话题与重要消息摘要，所有摘要均须引用有效消息。

8.8 任务状态与错误契约

queued → running → succeeded
                  → failed
                  → cancelled

running 任务仅在当前进程持有执行锁；
应用异常退出后，启动时将孤儿 running 标为 interrupted，允许用户重试。
错误码含义用户可执行动作
INSUFFICIENT_MESSAGES样本低于生成门槛扩大时间窗或取消
INSUFFICIENT_EVIDENCEAI 结论缺少可校验的原文引用重试或改为手动记录
PROVIDER_NOT_CONFIGURED无可用 Provider跳转设置
PROVIDER_AUTH_FAILED鉴权失败更新 Key，不自动重复请求
PROVIDER_RATE_LIMITED超过重试预算稍后重试
MODEL_OUTPUT_INVALID结构化输出持续无效重试或更换模型
WECHAT_NOT_RUNNING未找到可绑定的微信进程打开微信并停在未登录窗口后重新检测
WECHAT_LOGOUT_REQUIRED微信仍处于已登录状态在微信内退出账号，不能只关闭窗口
PROCESS_ACCESS_DENIED系统未授予所需读取能力查看平台授权说明；由用户决定是否重试
CAPTURE_TIMEOUT60 秒内未完成登录取钥重新发起；旧 Key 与本地数据保持不变
KEY_VALIDATION_FAILED候选 Key 无法只读打开目标数据库丢弃候选并重新抓取或查看兼容说明
KEY_STORAGE_FAILED验证后的 Key 未能加密保存重试保存或取消，不转为明文存储
WECHAT_ACCOUNT_CHANGED当前账号或数据目录与已保存连接不一致确认账号后重新取钥，不自动清空旧数据
SELF_IDENTITY_UNCONFIRMED当前微信本人映射未确认，无法可靠筛选本人消息确认身份并重新同步后再生成个人年度总结
WECHAT_VERSION_UNSUPPORTED微信版本未适配查看兼容说明

8.9 自动化调度（P1）

  • 启动时加载启用规则并计算 next_run_at；CRON 显式保存时区，默认本机时区。
  • 以 rule_id + scheduled_at 唯一约束防重；同一规则串行，不同规则可有界并发。
  • 应用未运行期间不承诺执行。重启后默认只记录 missed，不补跑，避免集中消耗 Token。
  • 自动任务和手动任务走同一 Service 与状态机；通知只包含任务名称、状态和本地跳转，不包含聊天正文。

8.13 与 TraceMemo 的关系
