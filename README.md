# WeTrace 使用文档

适用版本：0.1.0。本文根据当前项目代码整理，更新日期：2026-10-30。

WeTrace 是一个在电脑上读取本机微信聊天记录的桌面应用，支持浏览和搜索消息、查看聊天规律与群成员发言统计、向 AI 提问，以及生成 HTML 和 PNG 报告。应用以只读方式访问微信数据库，不会向微信发送消息。

## 1. 使用前准备

### 运行环境

- 当前项目的打包配置面向 macOS，已有安装产物为 Apple Silicon（arm64）版本。仓库中也包含 macOS x64 数据库库文件，但不能据此视为已有完整验证的 Intel 安装包。
- 本机需要有微信 4.x 的账号数据。密钥捕获工具包含微信 4.1.13 专用适配，其他版本能否捕获取决于实际兼容情况。
- 浏览本地消息、聊天脉络和发言统计无需配置 AI 模型。
- AI 对话与报告生成需要可用的文本模型；分析图片还需要图片理解模型；处理语音需要先下载应用提供的离线模型。

### 安装应用

项目当前的 `dist/` 目录包含：

| 文件 | 用途 |
| --- | --- |
| `WeTrace-0.1.0-arm64.dmg` | macOS Apple Silicon 安装镜像 |
| `WeTrace-0.1.0-arm64.zip` | 压缩版应用 |

打开 DMG 后，将 WeTrace 拷贝到“应用程序”并启动；也可以解压 ZIP 后打开应用。安装包应来自你信任的构建来源。

## 2. 首次连接微信

首次启动时，按照连接页完成环境检查、密钥捕获和消息同步。已经保存有效密钥的账号通常无需重复捕获。

### 第一步：确认数据目录

应用默认查找以下目录中的本地账号：

```text
~/Library/Containers/com.tencent.xinWeChat/Data/Documents/xwechat_files
```

进入应用后，可以在“设置 → 数据库与账号 → 数据目录”点击“更改”，选择实际数据目录。项目支持发现 `xwechat_files` 下的 `wxid_…` 账号目录，也支持直接选择账号目录。

只会读取这台电脑已保存的数据，不会从手机或云端补全历史记录。

### 第二步：按页面提示检查 SIP

当前密钥捕获方案需要读取微信进程内存，因此会检查 macOS 系统完整性保护（SIP）。SIP 开启时，应用会提供恢复模式操作指引。

关闭 SIP 会降低系统保护，应在了解影响后自行决定。需要操作时，按应用内指引进入恢复模式，在终端运行 `csrutil disable`，重启后返回 WeTrace。应用中的长按电源键进入恢复模式步骤面向 Apple Silicon 设备。

获取并验证密钥后，可在恢复模式终端运行 `csrutil enable`，再重启以恢复保护。已保存的有效密钥可用于后续读取；将来如果需要重新捕获，仍需满足捕获环境要求。

### 第三步：捕获数据库密钥

1. 启动微信，并在微信中退出当前账号，使其停留在未登录的登录页面。
2. 在 WeTrace 中点击获取密钥，按提示完成管理员授权。
3. 等待 WeTrace 显示监听已就绪，再回到微信点击“登录”。
4. 等待捕获完成，应用会验证密钥能否解密本地数据库。

操作顺序很重要：先启动监听，再登录微信。如果微信已经登录，先退出账号后重试。

数据库密钥保存在本机安全存储。账号不同或密钥失效时，需要针对相应账号重新获取。

### 第四步：同步本地消息

密钥验证通过后，点击同步按钮，等待应用读取本地会话并进入主界面。后续可以在“设置 → 数据库与账号”点击“立即同步”。

首次连接后还会建立全部聊天记录索引。数据较多时，消息浏览和索引建立可能需要等待；可在“数据库与账号”或“缓存与索引”查看进度。

## 3. 浏览和搜索消息

点击左侧“消息”，选择会话即可浏览记录。

- **会话分组**：群聊、联系人、服务与公众号、全部；默认展示群聊。
- **搜索**：在左侧搜索框输入联系人、群聊名称或聊天关键词，同时查看本地索引中的消息结果。
- **更早消息**：点击聊天区域顶部“加载更早消息”，逐步读取历史记录。
- **刷新当前会话**：点击会话名称旁的刷新按钮，重新读取并回到最新消息。
- **状态检查**：点击左下角头像，查看当前账号、密钥状态、聊天刷新状态和最近刷新时间。

应用会监听本地记录变化，并每 20 秒检查刷新。全部历史索引单独维护，每半小时增量更新，历史正文每天核对；因此最近消息刷新与历史索引更新并非同一进度。

“本地记录总数”与“已展示条数”含义不同：前者是本地可统计的会话记录，后者是当前已加载到聊天界面的消息，不相等通常是正常的。

| 快捷键 | 功能 |
| --- | --- |
| `⌘K` | 聚焦消息搜索 |
| `⌘,` | 打开设置 |

## 4. 聊天脉络与发言分析

### 聊天脉络

打开会话后，点击顶部“聊天脉络”。

1. 选择整个会话或某个成员。
2. 设置开始、结束日期，或选择近 90、180、365 天。
3. 查看每日消息量、活跃天数和规律变化提示。
4. 点击日期柱形或“查看当天聊天”，回看当天原文。

此功能基于本地记录和本机时区进行统计，不需要 AI 模型。明显变化的判断需要足够的历史参考，缺失的本地记录也可能表现为沉默；统计结果不能解释个人动机。

### 群聊发言分析

在群聊顶部点击“发言分析”，选择全部时间、今天、近 7 天、近 30 天或自定义日期。

可以查看发言总数、发言人数、成员排行与占比，并通过“复制统计”复制结果。系统通知不计入发言。

“未发言成员”依赖当前群成员名单。名单读取失败时会提示不可用，不能将其理解为没有未发言成员；当前成员名单也不等于历史任意时刻的成员名单。

## 5. 配置 AI 模型

进入“设置 → 模型配置”，保存文本或图片模型。可分别保存多份配置，并在使用时选择。

### 配置字段

| 字段 | 填写方式 |
| --- | --- |
| 配置名称 | 便于识别，例如“日常总结模型” |
| 模型模板 | DeepSeek、通义千问、Ollama（本地）或自定义；选择后会自动填写对应的地址与模型 ID |
| 接口格式 | 选择服务所支持的 OpenAI 或 Anthropic 兼容格式 |
| Base URL | 填写服务基础地址，不要附加 `/chat/completions` 或 `/messages` |
| 模型 ID | 填写服务提供的准确模型标识；图片配置需要支持图片输入的模型 |
| API Key | 填写相应服务的密钥，加密保存在本机 |

当前代码内置的默认文本模板如下。这些是应用预填值，实际可用性以服务端配置和连接测试结果为准。

| 模板 | 接口格式 | Base URL | 模型 ID |
| --- | --- | --- | --- |
| DeepSeek | OpenAI | `https://api.deepseek.com` | `deepseek-chat` |
| 通义千问 | OpenAI | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| Ollama（本地） | OpenAI | `http://localhost:11434/v1` | 手动填写本机可用模型 ID |

保存后，在“已配置模型”中编辑配置、测试连接或管理默认模型。编辑已有配置时，API Key 留空会保留原密钥。切换模板会重新填充地址与模型 ID，保存前请检查。

图片模型需要单独配置，文本模型能连接成功并不代表具备图片理解能力。当前语音功能使用固定离线模型，不通过此页面配置在线语音服务。

## 6. 向 AI 提问

有两种入口：

- 在会话顶部点击“问 AI”，带入当前会话背景。
- 点击左侧“AI 对话”，在问题中写明群聊或联系人、人物与时间范围。

示例问题：

```text
总结“产品讨论群”最近 7 天讨论的重点。
最近 3 天，小明在这个群里主要聊了什么？
整理这个会话中关于上线时间的讨论，并给出原文依据。
```

在输入框下方选择文本模型，输入问题后按 Enter 发送，Shift + Enter 换行。生成过程中可以点击停止；历史对话支持重新打开、重命名和删除。“AI 对话设置”可以调整对话风格和提示词。

当前界面对单个 AI 对话限制为 40 条对话消息，达到上限后请新建对话。应用一次处理一个 AI 对话生成请求，其他对话需要等待。

模型会按问题查询相关本地记录并整理回答。回答可能存在遗漏或误解，需要准确引用时请回看原文。

## 7. 生成聊天报告

### 按会话和日期生成

1. 点击“总结 → 生成报告”。
2. 在左侧选择群聊或联系人。
3. 选择今天、昨天、近 7 天或自定义日期范围。
4. 勾选需要处理的内容类型，等待本地记录加载完成并确认条数。
5. 选择基础语言模型；勾选图片时，还必须手动选择图片理解模型。
6. 如果是群聊，可选择总结整个群聊或某个成员。个人总结会结合所选范围内的群聊上下文。
7. 选择内容风格，可新增并保存自定义风格；模板决定视觉排版，风格决定内容表达。
8. 选择手机端或电脑端版式，点击“生成报告”。

| 内容类型 | 处理方式与前提 |
| --- | --- |
| 消息 | 纳入文字、链接、引用及其他消息内容 |
| 语音 | 在本机离线转写，将转写文本交给语言模型；需先下载离线模型 |
| 图片 | 发送至选定的图片理解模型；需配置并选择图片模型 |
| 视频 | 仅纳入统计，不解析视频内容 |

内容类型初始包含语音和图片。如果只需要文字报告，先取消勾选语音、图片和视频，即可减少准备步骤与处理量。

图片解析线程数默认是 3，可设置为 1–16 的整数。服务出现限流时可调低。已成功保存的图片理解和语音转写结果会在后续重试时复用。

### 只总结选中的消息

1. 打开“消息”中的目标会话。
2. 点击“选择消息生成报告”，勾选需要的消息。
3. 点击底部“生成所选消息报告”。
4. 在报告配置中确认所选范围，选择模型、风格与版式后生成。

此模式只总结所选消息，不自动添加其他消息或上下文。可以“返回调整选择”，也可以“改为按会话总结”。合并转发内容使用内部发言人进行处理。

### 查看进度与结果

右侧任务面板展示读取记录、离线语音识别、图片理解、模型分析以及保存文件的进度。任务提交后使用提交时的配置；生成期间继续调整页面配置不会更改当前任务。

报告默认同时输出 HTML 和 PNG；较长报告可能输出多张 PNG。完成后可点击“打开报告”“查看 PNG”或“打开所在文件夹”。

保存位置为系统“文稿”目录下的：

```text
WeTrace Reports/
```

回到“总结”首页，可以在“已生成报告”搜索会话或统计日期，并重新打开历史报告。历史列表重启后仍可查看。“报告模板 → 查看示例”展示的是模拟数据，不是你的聊天记录。

失败时查看任务面板中的错误、建议和素材处理说明；如果界面提供诊断文件路径，可据此定位问题。重新生成前先排除模型连接、日期范围和素材准备问题。

## 8. 图片、语音与本地索引

### 图片解密

当前图片解密在读取消息时自动启用，仅在本机处理。图片密钥与数据库密钥相互独立，应用会尝试从微信本地缓存中自动识别，不需要手动填写。

如果图片尚未下载，请先在微信中打开原图，再返回 WeTrace 刷新。解密图片的展示与将图片交给 AI 分析是两件事：生成报告并勾选图片后，才会使用所选图片理解模型处理。

### 离线语音转文字

进入“设置 → 语音转文字”，点击“下载模型”，等待 SenseVoice Small INT8 下载及校验完成，状态就绪后再生成包含语音的报告。

- 下载模型不会自动批量转写聊天语音。
- 报告处理时，语音在本机识别，成功转写结果写入本地缓存。
- 当前不支持通过设置切换在线语音服务或自定义语音模型。
- 可查看下载目录、进度与错误信息，也可删除模型文件。删除后如需处理语音，需重新下载。

该设置页目前存在“识别引擎：待接入”的静态说明，但报告流程已调用本地离线识别；请结合模型就绪状态和实际转写结果判断能否使用。

### 索引和缓存

在“设置 → 数据库与账号”或“缓存与索引”查看“全部聊天记录索引”。可暂停建立、继续建立或更新索引，暂停或退出后从已保存的批次继续，索引正文加密保存在本机。

“缓存与索引”同时展示语音转写条数、图片理解数量及其占用，以及本地缓存总大小。生成报告后可以点击“刷新统计”。不同模型或版本可能分别缓存，因此缓存数量不等于聊天素材总数。

当前“缓存目录更改”“清理图片缓存”“清空数据”等按钮仍为提示占位，不能用于实际迁移或删除本地数据。“索引管理”按钮会提示使用上方“更新索引”。

## 9. 账号切换与数据范围

在“设置 → 数据库与账号 → 切换账号”选择本机已发现的账号。如果目标账号没有有效密钥，需要先完成该账号的密钥捕获与同步。

“退出 WeTrace”用于退出当前应用的账号视图，不代表退出微信，也不能视为删除本地密钥、缓存或报告。

数据处理范围如下：

| 操作 | 数据去向 |
| --- | --- |
| 消息浏览、搜索、聊天脉络、发言统计 | 本机读取和计算 |
| 数据库密钥、模型 API Key | 本机安全存储或加密保存 |
| 离线语音识别 | 音频在本机识别，转写结果本机缓存 |
| AI 对话 | 问题、对话上下文及查询到的相关内容发送至所选模型服务 |
| 报告生成 | 所选范围内的文本、语音转写及分析所需内容交给语言模型；图片交给所选图片理解模型 |
| HTML、PNG 报告 | 保存到本机文稿目录，文件可能包含聊天内容 |

使用远程模型时，相应内容会离开本机；使用本地兼容服务时，去向取决于你配置的服务地址。分享报告前请检查其中的个人信息和聊天原文。

## 10. 常见问题

| 现象 | 处理方式 |
| --- | --- |
| 未找到微信数据或账号 | 确认本机微信已产生账号数据，检查数据目录，必要时在设置中更改 |
| 提示 SIP 已开启 | 根据应用指引和本文首次连接部分检查密钥捕获环境 |
| 未找到微信主进程 | 启动微信并停留在未登录页面，再开始捕获 |
| 捕获超时或没有有效密钥 | 先退出微信账号；先等监听就绪，再登录；仍失败时检查微信版本适配和管理员授权 |
| 已保存密钥无法解密 | 确认选中了正确账号，并重新获取对应账号密钥 |
| 最近消息未出现 | 刷新当前会话，或在数据库与账号中立即同步；查看左下角账号状态中的刷新错误 |
| 搜索或报告缺少历史记录 | 检查索引进度并更新索引；确认这些记录本来就保存在这台电脑上 |
| 图片无法显示 | 先在微信中打开原图使其下载，再回到应用刷新；重新获取数据库密钥不等于修复图片密钥 |
| 报告提示缺少图片模型 | 配置并选择图片理解模型，或取消勾选图片 |
| 报告提示需要离线语音模型 | 先下载模型并等待就绪，或取消勾选语音 |
| 当前筛选没有记录 | 检查会话、日期、内容类型和手动选择范围，等待索引或记录加载完成 |
| 模型连接失败 | 核对接口格式、Base URL、模型 ID、API Key 和服务可用性；Base URL 不要填写完整请求端点 |
| 图片解析限流或失败 | 调低图片解析线程数，检查图片模型能力与服务限制，再重试 |
| 首次打开或建立索引较慢 | 观察索引进度；可以暂停索引后继续，避免反复重新初始化 |

## 11. 从源码运行（开发者）

项目使用 Electron、React、TypeScript 和 pnpm。运行前安装 Node.js 与 pnpm。项目未声明固定的 Node.js 最低版本，请使用满足当前依赖要求的版本；部分测试使用 `--experimental-strip-types`，需要支持该选项的 Node.js。

在项目根目录执行：

```bash
pnpm install
pnpm dev
```

构建、预览和打包：

```bash
pnpm build
pnpm start
pnpm package
```

`pnpm start` 预览已经构建的产物，需先执行构建；`pnpm package` 会先构建，再按 `electron-builder.yml` 生成 macOS DMG 和 ZIP 到 `dist/`。原生库及密钥工具来自 `resources/`，应完整保留。源码运行仍需满足前述微信数据与密钥要求。

常用检查命令：

| 命令 | 用途 |
| --- | --- |
| `pnpm typecheck` | TypeScript 类型检查 |
| `pnpm test:local` | 本地自检 |
| `pnpm test:startup` | 启动环境相关检查 |
| `pnpm test:index` | 索引相关检查 |
| `pnpm test:patterns` | 聊天脉络逻辑检查 |
| `pnpm test:report` | 报告相关检查 |

部分检查会启动 Electron，或依赖本地环境、数据与模型配置。本文根据源码核对功能与操作流程，未将所有平台、微信版本及模型服务视为已经实测通过。
